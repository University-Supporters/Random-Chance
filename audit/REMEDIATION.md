# 보완 결과 (2026-09-19)

## 완료
- Upstash `upstash-kv-cerise-ferry` (Free)를 random-chance의 Preview, Production에 연결. Vercel Connections 표에서 두 환경과 KV 환경변수 생성 확인. 비밀값은 열람하거나 기록하지 않음.
- KV 저장을 Lua 비교 후 쓰기로 변경해 서버 간 갱신 충돌을 재시도하고 중복 검사도 최신 데이터에서 재실행.
- 매 저장 시 원격 미러와 최근 40개 이력 보관. 수동·복원 직전 백업 별도 보관. 원격 장애 시 임시 로컬 저장으로 성공 응답하지 않음.
- 로컬 원자적 쓰기·프로세스 간 잠금·매 저장 스냅샷. 전부 손상된 경우 자동 초기화 대신 오류 및 외부 백업 복원 지원.
- 일반 목록에서 당첨자 제거. 로그아웃 취소 목록, 로그인 제한, 비밀번호 버전을 공유 DB에 저장. 복원으로 비밀번호 및 세션 취소 상태가 되돌아가지 않도록 보호.
- 영구 저장소 없는 Vercel에서 응모 차단. 관리자 로그인과 복구 경로는 유지.

## 검증
- 3개 실제 Node 프로세스 + 모의 Redis REST/Lua 계약 테스트: 동시 등록 500/500 보존 (약 17~19초), 동일인 경합 1건만 등록.
- 원격 미러/이력 복구, 저장소 장애 시 등록 차단, 서버 간 로그아웃 반영, 비밀번호 변경 및 복원 시 인증 상태 유지 통과.
- 전체 실행 24개 중 신규 테스트의 응답 경로 오타로 1개 실패. 오타 수정 후 해당 파일 2개 재실행 모두 통과. 나머지 22개는 전체 실행에서 통과.
- 프로덕션 빌드 성공.
- 브라우저: 1366×600, 1366×640, 1920×940, 768×600, 390×700 스크롤 검사 통과. 입력 검증, 계정 없음, 5초 초기화, 상급 탭 인증, 스냅샷, 백업 다운로드, 로컬 금고, 응모 화면 복귀 통과.

## 아직 완료되지 않은 운영 검증
- 로컬 수정 코드는 운영 배포에 반영하지 않았음. 저장소 연결은 기존 실행 중 배포가 새 환경변수를 사용한다는 증거가 아님.
- 현재 운영 데이터를 백업·이관하지 않았음. 새 저장소를 사용하는 배포 전에 기존 참가자가 있는지 확인하고 백업해야 함.
- 실제 Upstash 구성의 부하/장애 테스트는 미실시. 모의 테스트 결과를 실제 서비스 성능 보증으로 해석하면 안 됨.
- Preview와 Production은 승인된 대로 같은 DB를 공유하므로 Preview에서 실제 데이터에 영향을 주는 테스트를 하면 안 됨.
- 기본 비밀번호 정책은 유지. 상급 관리자 화면에서 별도 강한 비밀번호 설정 가능. 원격 저장소 전체 삭제/계정 상실까지 자동 복구할 수 없으며 별도 다운로드 백업이 필요.
- Git 명령 실행 및 PR 생성 없음.
